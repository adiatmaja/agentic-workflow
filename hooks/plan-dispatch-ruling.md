OWNER RULINGS (2026-10-10 cost-led tiering; 2026-10-17 parallel-by-default, one worktree per task) - agent, effort, review and parallelism in plans. They override the skill text where they disagree.

WHEN WRITING A PLAN (writing-plans): every task carries FOUR lines directly under its heading:
  **Agent:** `impl-sonnet-medium` (sonnet, medium) - why this tier fits THIS task's complexity (one clause)
  **Worktree:** own - `t3-<slug>`, base = main at dispatch (`isolation: "worktree"`) | none (inline, trivial)
  **Review:** plan-level (default) | per-task `review-first` (only for impl-opus-* tasks)
  **Parallel:** wave 2 - alongside Task 4; after Task 1 (needs its OUTPUT: `assets/x.js` exports `foo()`)
- Worktree is the default for every agent task; "none" only where Agent is inline. The name is the task number plus a slug; the base is whatever main is when the wave starts, so a wave-2 task sees wave-1's merges. The Execution schedule table gets a "worktrees" column and ends with the integration order (one branch at a time).
- Name a CONFIGURED agent, never a bare model or built-in type; write its model and effort, re-derived with: grep -H -E '^(model|effort):' ~/.claude/agents/*.md
- DEFAULT is impl-sonnet-medium. Go DOWN to impl-sonnet-low (mechanical, complete code in the plan) or impl-haiku-medium (DOCS ONLY). Go UP to impl-opus-medium only for a load-bearing invariant or seam where no test would catch a silent error, and impl-opus-high for the one task whose undetected error invalidates everything after it. State the reason for any opus line; tier by COMPLEXITY, never by an open item's priority tag (owner 2026-10-10).
- **Agent:** inline is for the TRIVIAL only: a one-line registry edit, a doc tweak, an exactly located fix in a file the session already has open. Everything else is an agent in its own worktree, even a single-file task.
- PARALLEL BY DEFAULT (owner 2026-10-17: "that parallelization is the most important part"): a task waits only on a task whose OUTPUT it needs; same file, different sections, is NOT a dependency (the merge regenerates generated maps). Find the safe split rather than serialising; size is not the test. Parallel runs do multiply spend - that is the accepted cost; save on tier and effort per run, never on run count. Ceiling = measured machine load. The plan ends with an "## Execution schedule" table: wave, tasks, agents, what the wave waits for.
- Full cold-start context per task: files and symbols (symbol + grep -n; line numbers are claims), the project rules that bite it, exact TARGETED test commands with expected output (each under 5 min), and what done looks like.

WHEN EXECUTING A PLAN (subagent-driven-development, executing-plans): TWO LAYERS. The top-level session dispatches each task's agent itself, EVERY implementer with `isolation: "worktree"` (hook-enforced; the WorktreeCreate hook places it at <workspace>/.worktree/<project>/<name> and copies .env/var), every unblocked task of a wave in ONE response, and does only trivial inline tasks itself. This OVERRIDES subagent-driven-development's "Never dispatch multiple implementation subagents in parallel" - that rule assumes one shared worktree; here each implementer has its own, and the session integrates one branch at a time: rebase, lint + affected tests on the MERGED tree, fast-forward main, remove the worktree. using-git-worktrees: the preference IS declared - never ask for consent. Each brief requires the implementer to run its own targeted gates in the FOREGROUND, commit by explicit path, and return a report of at most 200 words (files, commits, gate counts, deviations). The session reads the report plus `git diff --stat`, re-runs the gates, merges one at a time. Dispatch ONE `plan-orchestrator` only when 8+ agent tasks REMAIN (count what is left, not the plan's total; finishing or merging a stopped round is session work) or when the session is already past ~150k context. Dispatch the subagent_type each **Agent:** line names and OMIT `model`; the skill's "always specify the model explicitly" does NOT apply. Never Monitor, sleep or poll an agent. REVIEW: one `review-first` over the whole plan diff at the end (per task only for impl-opus-* tasks); fix small exactly-located findings inline; otherwise fix 1 = same agent fresh, fix 2 = one step up; a failed opus-high fix returns to the session. UI-only work: one review, no re-check.
